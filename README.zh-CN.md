# dsh-budget-watcher

[English](README.md) | **简体中文**

一个 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）插件。它在对话窗口上方浮一个小面板，显示
**你的 API 账户还剩多少余额**，以及 **你刚刚跑的那几轮对话实际花了多少钱**。

![展开状态的面板](docs/screenshot.png)

*真实账户上的展开面板：余额、本轮花费与会话总花费、两个「烧」值，以及按本轮实际耗时绘制的实时烧曲线。截图版本 `0.6.2`。*

![折叠成胶囊的面板](docs/screenshot_pill.png)

*一键折叠（或双击标题栏）后只剩状态点和金额。状态点保留颜色，所以花钱告警在折叠状态下依然可见。*

面板标题就是 *DeepSeek balance*，所以金额没有副标题，也没有第二行。数字取自 DeepSeek 公开余额接口的
`total_balance`：**充值金额 + 赠送额度**，也就是真正决定下一次调用能否成功的那一个数。两者**不分开显示**——
只报一个数才是诚实的做法：单看 `topped_up_balance`，一个靠赠送额度正常运行的账户会显示 `0.00`，等于把好账户说成没钱了。

## 它显示什么

下表中的每个数字都直接取自上面两张截图，是真实读数而不是示例。

| 元素 | 含义 |
| --- | --- |
| `¥51.33 CNY` | `total_balance` —— 全部余额：充值金额 **加上** 赠送额度。这是标题数字，也是唯一的余额行。 |
| 绿点 | `is_available: true`，账户可以正常调用 API。 |
| 黄点 | 余额数据过期、上次检查失败、`is_available` 为 `false`，或实时烧超过警告阈值。 |
| **红点** | 触发了消费上限，插件**已中断该轮任务**。只有这一种情况会用红点。 |
| 红点（另一种） | 什么都读不到，且屏幕上也没有上一次的值。 |
| `just now` | 宿主最后一次拿到应答的时间。过期数字一定标注出来，绝不当作当前值展示。 |
| `this turn ≈¥0.12 / ¥13.93 · 22 turns` | 斜杠前是**你正在等的这一轮**的花费，斜杠后是**整个会话**（含两者派生出的所有子代理）。放在一行，因为「这次花了多少」和「一共花了多少」本来就是一件事。 |
| `live burn ≈¥0.00/h · 15s` | 最近 15 秒的花费折算成每小时。这是发现突发消费的指标，也是两个阈值的判断依据。这里显示 `¥0.00/h` 是因为那 15 秒内没有任何一步结算——**这是真实读数，不是故障**。任务进行中时旁边有一个跳动的圆点。 |
| `average burn ≈¥6.40/h · 1:09` | 本轮花费除以本轮耗时：¥0.12 / 1 分 09 秒。这是滚动平均值，在轮次结束时定格。 |
| 图表 | 把 `live burn` 画在本轮的耗时轴上，`0:00 → 1:09`。蓝线锚定在原点——那时还没花过钱；琥珀色 `warn ¥15` 是警告阈值。 |
| `1 turn(s) unpriced` | 出现了价目表里没有的模型，于是这些轮次只报告、不猜测金额。 |
| `session ¥15.12 · 4 turns` | 会话总计单独占一行——仅在还没有轮次可以和它配对时出现。 |
| `Not available for API calls` | `is_available: false`。 |
| `No API key is configured…` | 宿主没找到密钥，提示信息会说明该设置哪个凭证引用名。 |

## 「烧」是什么

本插件有两个速度概念，中文都叫「烧」，英文都叫 **burn**，统一指**成本燃烧率**——也就是**单位时间内花掉多少钱**，
而不是花了多少钱。下文一律简称「烧」。

一个发散成六十个子代理的研究型任务，从对话窗口里是看不出来的：只有一轮对话开着，一个字都没回，余额却在往下掉。
光看余额只能知道**在花钱**，不知道**花得多快**——而后者才是你决定要不要停下来的依据。

面板用四个数字回答这个问题，全部来自已经在磁盘上的数据：

- **`this turn`** —— 你正在等的这一轮已经花了多少。随着每一步结算而增长，因为用量是按条助手消息上报的，而不是按轮次。
- **`real-time burn`（实时烧）** —— 最近一个窗口（`burnWindowMs`，默认 **15 秒**）的花费折算成每小时。
  这是**突发消费探测器**，两个阈值都对它生效。它故意取短窗口，因此天生抖动：窗口内没有任何结算时它会读作 `0`，
  这是如实反映，不是坏掉。用 15 秒的代价换来「几秒内发现问题」而不是「几分钟后」。
- **`average burn`（平均烧）** —— 本轮花费除以本轮耗时。它每秒按实时时钟重算一次，并在轮次结束时**定格**，
  这正是两个已完成任务可以互相比较的原因：一轮的烧是这件事本身的事实，而不是这个配置文件最近的心情。
- **`session`** —— 本会话的每一轮**加上它底下的每一个子代理会话**。发散的轮次是在子代理里烧钱的，
  只看你面前这个会话，看到的只会是平静而不是火情。`N agents` 后缀告诉你有多少个还在跑。

之所以要分成两个烧而不是一个，是因为一个数字会同时掩盖两件事：把 15 秒窗口平均进整轮均值，得到的数既不够即时、抓不住失控，
也不够稳定、比不了任务。

因为整套东西的重点是**认出贵的那一轮**，所以 **`this turn` 和两个烧都计入该轮派生出的代理**，按**时间窗口**归因而不是按轮次编号。
子代理有自己私有的轮次编号，只累加对话自身的轮次，会在六十个代理同时烧钱时报出一个平静的速率。

设置页会把最近的轮次按**烧从高到低**排出来——花费、烧率、耗时——所以贵的任务在事后也认得出来，而不是只在跑的时候认得出来。

### 两个阈值，以及会掐断任务的那个

两个阈值都以**余额本身的币种**表示：人民币账户就是元/小时，美元账户就是美元/小时。

- **`burnWarnPerHour`** 让状态点变琥珀色，并给实时烧上色。纯提示，不做任何动作。
- **`terminateAbovePerHour`** 更进一步：实时烧越过它时，插件会**中断正在跑的这一轮**，效果等同于你按下停止；
  状态点变红。它**默认关闭（`0`）**——中断任务是破坏性操作，而它依据的是一个估计值，所以必须由你主动打开。
  真的触发时：中断按轮次编号**上锁**，一个失控的轮次只会被中断一次而不是每次轮询都中断；你已经排队的输入会被保留；
  会话日志会记下 `turn/end` 与 `reason: { kind: "aborted", reason: { kind: "hook", reason: "dsh-budget-watcher/over-budget" } }`，
  于是这一轮的结束有明确原因，而不像一次崩溃。

## 图表怎么读

图表在数字下方、刷新行上方，把这一轮的实时烧画在它自己的耗时轴上，也就是这一轮对话的 `d(币种)/dt`。默认开启，
可以用 `graphEnabled` 关掉。

它占满面板内容区的宽度，所以和 `this turn` 那一行左右对齐，而且**不会把面板撑得比文字更宽**——这正是面板能保持窄的原因。

- **横轴是这一轮本身，而不是一个滑动窗口。** 任务运行时它每秒增长，轮次一结束就停住，因此图画的是一个任务从开始到结束的全过程，
  而不是一个会忘事的滑动窗口。定格的图表就是一轮已完成任务的完整历史。
- **纵轴只升不降**，并且只在出现新高时才重新缩放。它绝不会在任务进行中把刻度缩小到曲线下方，那会让一个下降的烧看起来像悬崖。
  网格线落在 1、2、5 乘以 10 的幂上，峰值写在图表的无障碍描述里。
- **蓝色**是实时烧，**琥珀色**是 `burnWarnPerHour`，**红色**是 `terminateAbovePerHour`——只有它大于 `0` 时才画，
  因为一条「关闭」状态下的停止线等于在宣称一件不可能发生的事。每条线旁边的说明文字取该线自己的颜色，所以两种主题下都读得清。
- **纵轴上的每个刻度用同一个小数位**，由步长决定，所以轴上会读作 `¥0 / ¥20 / ¥40`，而不是 `¥10` 压在 `¥5.00` 上。
- **曲线锚定在坐标原点。** `t=0` 时还没有花过钱，那里的烧如实为零；如果从第一个结算步开始画，图的左半边看起来会像缺数据。
- **高于量程的阈值会被钉在顶边**并用 `▲` 标出，而不是干脆不画。把你设的那条线藏起来，比显示一条超量程的线更糟。
- 这条线和 `live burn` 那一行是同一个窗口值，所以两者不可能互相矛盾；宿主在每个结算步采样，面板每秒把它延伸到「现在」。

## 数字从哪来

DeepSeek 在每条助手消息上都上报精确的 token 用量，DSH 会把它写进会话日志。插件读日志，再乘以 DeepSeek 公布的价目：

```
成本 = 未命中缓存的输入 × 缓存未命中单价
     + 命中缓存的 token × 缓存命中单价
     + 输出 token      × 输出单价
```

有两个细节决定它是「估算」还是「算错」：

- **DSH 的 `inputTokens` 是*未命中缓存*的那一半。** 缓存桶是分开的。把缓存读取量从 `inputTokens` 里减掉——看起来很自然的算法——
  会让命中良好的轮次里未命中那一半归零，恰好少报最该盯的那些轮次。`dsh-llm-deepseek` 把恒等式写得很清楚：
  `totalTokens = inputTokens + outputTokens + cacheReadTokens + cacheWriteTokens`。
- **重试也计费。** 失败的一次尝试会以 `assistant/attempt` 落地，这个事件**没有** `usage` 字段，数字只存在于它流的最后一个
  `usage` chunk 里。只读 `usage` 会静默漏掉每一次重试的成本。

### 没有汇率

DeepSeek 的价目表**同时**公布人民币价和美元价，所以插件两张表都带，按你选择的币种计价——选 `auto` 时，按当前展示钱包的币种。
整个插件**不涉及任何汇率**，这也意味着两种币种的数字**不是彼此的换算结果**：flash 空闲时段的输出价是 $0.60 或 ¥4
（隐含汇率约 6.67），而真实汇率更接近 7.2。只支持这两种币种，其他一律回落到美元表。

高峰/空闲单价按每次调用自身的时间戳判定（高峰为 UTC 01:00–04:00 与 06:00–10:00，周一至周五，
即北京时间 09:00–12:00 与 14:00–18:00）。`reasoningTokens` 会被记录但绝不单独计价：它是输出 token 的子集。

## 安装

```bash
# 从本地目录安装（开发用）
dsh plugin --profile <你的 profile> add link:/path/to/dsh-budget-watcher

# 从 GitHub 安装
dsh plugin --profile <你的 profile> add github:NeutronStar714/dsh-budget-watcher
```

装好后重启该 profile。**DSH 桌面应用自带的 profile 不能从命令行安装**，它只由 Electron 应用管理，请改用
**设置 → 插件**页面。

### 卸载

```bash
dsh plugin --profile <你的 profile> remove dsh-budget-watcher
```

临时停用而不卸载：

```yaml
- id: budget-watcher
  disabled: true
```

## API 密钥

插件需要一个能读余额的 DeepSeek API 密钥。默认从凭证引用 `DEEPSEEK_API_KEY` 读取，也可以在配置里直接写 `apiKey`。
密钥只在宿主进程内使用，**永远不会发送到页面**：设置表单只被告知「是否已设置」。

## 配置

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `provider` | `deepseek` | 读哪个 API 账户。目前只实现了 `deepseek`。 |
| `apiKey` | *(空)* | 直接写死的密钥。为空时改用下面的凭证引用。 |
| `apiKeyEnv` | `DEEPSEEK_API_KEY` | 存放密钥的凭证引用名。 |
| `endpoint` | *(provider 默认)* | 覆盖余额接口地址，用于对着测试服务器联调。 |
| `refreshIntervalMs` | `60000` | **宿主**复用同一个余额应答多久之后才再次请求 DeepSeek。最小 `15000`。它管的是**上游调用**，不是面板轮询频率。 |
| `requestTimeoutMs` | `10000` | 单次余额请求的超时。 |
| `currency` | `auto` | 成本数字与两个阈值用哪种币种显示。`auto` 跟随当前展示的余额钱包；也可以强制 `CNY` 或 `USD`。取值是封闭集合，因为 DeepSeek 只公布这两种币种的价格。 |
| `allowNonLoopback` | `false` | 允许在非回环地址上提供接口。默认关闭。 |
| `costEnabled` | `true` | 根据 provider 已经上报的用量估算轮次成本。本身**不消耗任何 token**。 |
| `graphEnabled` | `true` | 在面板里绘制实时烧图表。关掉后所有数字都还在。 |
| `burnWindowMs` | `15000` | **实时烧**的窗口长度，毫秒，最小 `5000`。故意取短：它才是抓突发消费的那个数。 |
| `burnWarnPerHour` | `2` | 每小时花费超过它就变琥珀色，单位是余额本身的币种。`0` 表示关闭警告。 |
| `terminateAbovePerHour` | `0` | 每小时花费超过它就**中断当前轮次**，单位是余额本身的币种。`0`（默认）表示关闭。 |

**没有汇率选项，因为不存在汇率问题。** 成本直接取自 DeepSeek 公布的**人民币或美元价目表**，与当前展示的余额币种一致。

## 设置面板

面板上的**齿轮按钮**会在 DSH 右侧栏打开一个 *Budget* 标签页：上面每个选项都是一个可编辑字段，带保存按钮。
齿轮只在确实能注册出标签页时才出现，所以它永远不会是一个点了没反应的控件。

时长按你思考的单位显示（余额缓存和实时烧窗口都是**秒**），保存时换算回去。API 密钥字段是只写的：初始为空，留空表示
*不动它*，清空则从配置里删掉密钥。运行中的密钥值从不发到页面。

`Currency` 是一个只含 `auto` / `CNY` / `USD` 的**下拉框**，不是文本框：那正是 DeepSeek 公布价格的两种币种，
其他取值只可能是错的。两个阈值旁边的单位会写出余额实际使用的币种。

表单**可以滚动**，保存按钮固定在底部，所以无论设置项和最近轮次列表多长，保存都不会够不到。轮次列表另有高度上限，独立滚动。

保存走 DSH 自己的配置编辑器，因此改动会落到你 profile 的 `cordis.patch.yml`，并由正常的加载流程生效——
和你手工编辑的是同一个文件、同一套机制：

```yaml
- id: budget-watcher
  name: dsh-budget-watcher
  config:
    currency: CNY
    burnWindowMs: 15000
    burnWarnPerHour: 3.5
    terminateAbovePerHour: 0
```

设回默认值的项会被删除而不是写入，于是该行重新回到「继承默认」。改配置**不需要重启 DSH**。

## 已知限制

完整的 55 条限制在英文 [README](README.md#known-limitations) 中，**那里是权威版本**。下面按主题重新编排，
与英文版一一对应但措辞更紧凑；两者出现差异时以英文版为准。

### 余额

1. **数据来自公开的余额接口。** 不是 DeepSeek 官方支持的 API，它可能随时变更或消失。接口变了，插件会报错，而不是猜测。
2. **接口返回的 `total_balance` 会被原样显示，不做重算**，所以显示的就是返回的值。
3. **没有 `is_available`，也没有赠送额度的有效期信息。** 赠送额度过期、未来计费方式变化都在它之外。
4. **余额是粗略的。** 接口只给两位小数，且可能有结算延迟。
5. **余额接口返回的是 API 密钥账户的余额**，不是网页登录的开放平台账户余额。
6. **是轮询而不是推送。** 没有 SSE 流，所以面板靠轮询。这里有两个刻意分开的间隔：**面板**每隔几秒轮询一次自己的本地宿主接口
   （任务运行时 2 秒，空闲 3 秒），好让新提示词被及时发现；而 `refreshIntervalMs`（最小 15 秒、默认 60 秒）是**宿主**
   复用同一个余额应答多久才再次调用 DeepSeek。把两者混为一谈正是 `0.6.3` 修掉的 bug：面板继承了 60 秒的轮询，
   看上去像卡住，直到有人按下刷新。
7. **除同源围栏外，接口没有鉴权。** 它不在 DSH 需要鉴权的 `/api` 前缀下，插件自己做了回环地址 + 同源检查。
   它只返回余额数字，从不返回凭证。若你的部署绑定了非回环地址，该接口会在那个网络上应答，除非保持 `allowNonLoopback` 关闭。
8. **围栏相信自己的 Host。** 只有绑定在回环地址上时才成立。
9. **页面会显示余额，但它本身并不安全。** 任何能访问这个 GUI 的人都能看到账户余额。
10. **只实现了 DeepSeek。** 其他 provider 都未实现。

### 客户端界面

11. **浮层是直接操作 DOM 定位的**，不是 DSH 的布局系统。拖拽位置保存在 `localStorage`，清理浏览器数据会重置它。
12. **折叠成胶囊时刻意不可拖拽**，这样它就不会被误碰。
13. **没有本地化。** 面板文案硬编码为英文（本文件是文档翻译，不是界面翻译）。
14. **宿主模块在进程生命周期内只导入一次。** 因此修改已加载插件的源码必须重启 DSH 才生效，而客户端那一半每次请求都从磁盘重新提供，
   于是它会心甘情愿地给一个过期宿主画界面。每个 payload 都带 `pluginVersion` 就是为了让这件事可见。
15. **DSH 桌面应用自带的 profile 不能从命令行安装**，它由 Electron 应用独占管理。

### 成本估算

16. **价目表是快照，不是订阅。** 价格写在 `lib/cost.js` 里并记录读取日期（`PRICING_READ_ON`），该日期会出现在 payload 中。
    DeepSeek 改价不会被自动发现，面板会继续自信地报旧价。
17. **没有建模中国法定节假日。** 高峰/空闲按 UTC 窗口计算，但节假日的排除没有做——官方文档没有公布这份日历且每年变化。
    `PRICING_READ_ON` 之后的第一个节假日，工作日会按高峰计价，也就是**高估**成本。对花钱告警来说这是安全的方向。
18. **价目表是两张公布的表，不是彼此的换算。** 插件两张都带，按你选择的币种计价，选 `auto` 时跟随当前展示的余额钱包。
    数字彼此不是换算结果，只支持这两种币种，其他回落到美元表。
19. **只统计当前活跃的 agent 树。** 花费归因于轮询时仍然活着的会话，加上本进程已经记住的会话。
    在插件加载**之前**就结束的发散任务不在活跃列表里，它的子代理花费不会计入会话总计——根会话自己的轮次仍然会算。
20. **记住的总计可能超过活跃总计。** 这是刻意的：已结束的子代理会继续贡献，这样数字永远不会回落。
21. **`ownEvents()` 与 `snapshotEvents()` 在 DSH 中已废弃。** 它们是插件唯一能读整个日志的途径，DSH 自己的说明禁止新的生产调用。
    每次调用都包了 try/catch：一旦未来版本移除它们，成本部分消失而余额继续工作。
22. **没有价格模型的轮次只报告不估算**，显示为 `N turn(s) unpriced`。静默的零会被读成「那一轮免费」。
23. **重试的模型是推断出来的。** `assistant/attempt` 事件不带模型名，因此按该轮模型计价，再回落到会话自己的请求上下文。
24. **推理 token 不单独计价。** DSH 确实会填 `reasoningTokens`，但它是输出 token 的子集，重复计价会高估。
25. **按 token 计价，而 token 的粒度是模型自己的。** 这是唯一可用的粒度。
26. **多模态输入只按文本计价**，图片等的计价方式不在统计范围内。

### 宿主插件与加载

27. **本插件是普通 Cordis 插件**，不依赖任何私有 API。
28. **配置校验依赖 `@deepseek-ai/schemastery` 能被解析。** 它被声明为 peer dependency，因为 DSH 的 profile 解析会拦截 peer 名；
    缺少它时 `Config` 会静默变成 `undefined`，配置就永远不会被校验。
29. **不要添加 `@deepseek-ai/dsh*` 作为 peer**，兼容性闸门会检查这些范围，不满足时会静默跳过整行。
30. **`.volatile()` 刻意没有使用。** 它能让改动不重载 fiber，但字段会变成必须每次读取时解引用的 getter 对象；
    普通字段加一次 fiber 重载更简单，也确实验证过生效。

### 轮次成本与「烧」

31. **烧是累计平均，不是瞬时速率。** 成本随每个结算步成块到达，瞬时速率会每步一个尖峰、步与步之间读作零。
32. **运行中的轮次在步与步之间烧会衰减。** 分子只在结算时变，分母每秒都在变。
33. **实时数字在浏览器里计算。** 宿主发来花费和轮次起点，面板本地以 1 Hz 走时重算，因此显示是活的而不需要每秒一个请求。
34. **一轮的数字包含它的子代理，按时间窗口归因。** 这是刻意的，但意味着一个更早轮次的长命子代理，只要它的调用落在本轮窗口内就会被算进来；
    而轮次结束**之后**仍在继续的工作不算，所以定格的数字可能低估一个活得比根轮次更久的发散任务。
35. **实时烧会闪。** 15 秒窗口在窗口内没有任何结算时读作 `0`，任何一步响应慢于 15 秒都会这样。这是真实读数，不是 bug；
    这也正是需要 `average burn` 作为稳定对照的原因。
36. **轮次历史有上限且以根会话为范围。** 对比表保留最近 10 个已结束轮次，不持久化，重启即空，也无法跨会话比较。
37. **走时时钟信任宿主。** payload 带宿主的 `serverNow`，页面据此校正偏移，因此浏览器时钟漂移不会扭曲轮次时长。
    它假设两者在同一台机器上，这对本插件提供的回环接口成立。

### 中断轮次

38. **轮次定位是建议性的，不是原子的。** `Agent` 比任何一轮活得久，所以持有引用标识的是 *agent* 而不是轮次；
    在读取实时烧和调用 `cancel` 之间存在真实窗口，轮次可能已经结束、后继轮次已经开始，而 API 里没有任何东西能「取消第 N 轮」。
    插件在调用前后各采样一次开放的轮次边界，这不能阻止误伤，但能把一次静默误伤变成一条 `raced-next-turn` 日志。
39. **默认关闭，在看到真实烧率之前应该保持关闭。** `terminateAbovePerHour` 默认 `0`。中断任务具有破坏性，
    而它依据的是由 15 秒窗口算出的估计值，阈值设低了会打断正常工作。先设 `burnWarnPerHour`，观察你的轮次实际烧多少，再把上限设在它之上。
40. **检查发生在读接口上。** 是否中断是在余额 `GET` 里决定的，这是读操作带副作用，并不优雅。烧只在那里计算，
    替代方案是再开一个定时器把同一份账重算一遍。默认关闭是让这个折中可以被接受的原因。
41. **退出点是协作式的。** `cancel` 会中止在途请求并排空或跳过工具调用，但已经在执行的工具是被排空而不是强杀，
    而且 provider 的 socket 是否立刻断开取决于适配器。轮次可能在停下之前先跑完当前这个工具调用。
42. **子代理不保证被停掉。** 前台进程内的子代理会继承父级的 abort 信号，确实会停；后台和可继续的子代理可能不会。
    插件只停根轮次，不遍历整棵树，所以发散任务的后台代理可能比被中断的那一轮活得更久。
43. **每轮只停一次，且不会重新上锁。** 触发按轮次编号锁存，因此一个轮次最多被中断一次。之后的轮次可以正常被停，
    但如果**同一个**轮次在被取消后仍然继续，它不会再被停第二次。

### 设置面板与图表

44. **设置表单自己负责滚动。** 侧边栏给标签页一个有界高度且不为它滚动，所以表单是滚动容器、保存按钮钉在它底部；
    最近轮次列表单独限高并独立滚动。没有这套安排，折叠线以下的内容——包括保存——根本够不到，这正是它修掉的 bug。
45. **图表需要有轮次才画。** 会话里还没有轮次时没有时间轴可画，于是图表不出现而不是空着。它也不持久化：
    序列每次轮询都从会话日志重建，所以能挺过面板重载和 DSH 重启，但本身不存储在任何地方。
46. **曲线是窗口速率，所以会降也会升。** 它和 `live burn` 行是同一个 15 秒数字，因此一段长于窗口的安静期会把曲线拉回零附近。
    这是速率在如实反映，不是图表出故障。
47. **纵轴锁在最高水位。** 它只在出现新最大值时变化，所以回落的速率不会把刻度一起拉下来——曲线在固定画框内下探，
    而不是整张图跟着你重新缩放。代价是：早期尖峰把上限顶高之后，长轮次后段的细节看起来会比较平。
48. **高于量程的阈值是钉住显示，而不是省略。** 它贴在顶边、虚线并标 `▲`。钉住的线读不出数值，真实数字写在标签里。
49. **序列是抽稀，不是截断。** 发散任务可能结算数百步，超过 240 个采样后宿主均匀抽稀，保留整轮形状而不是只保留前半段。
50. **网格线是整数，不是数据的等分。** 步长取 1、2、5 乘以 10 的幂，任何量级下都可读，但也意味着最上面那条线通常高于峰值而不是正好落在峰值上。
51. **图表高度是比例，面板宽度是文字决定的。** 图表是内容框的固定比例（240:100），所以它跟随最宽文字行要到的宽度。
    因此很窄的面板会把坐标标签一起缩小——图表宽度低于约 100 个 CSS 像素时就不舒服了，诚实的做法是关掉图表。
52. **面板宽度由最长的那行文字决定**，实践中就是 `this turn ≈¥0.78 / ¥13.05 · 19 turns`。面板里没有别的东西能把它撑宽：
    图表被刻意阻止贡献自己的固有宽度，余额和标题都更短。那行变长，面板就跟着变宽。

### 货币

53. **余额那一行无法跟随 `currency` 设置。** 成本是算出来的，所以可以用你选的币种表达；余额不是算出来的——
    它是接口按账户自己的币种返回的数字——因此只能以账户实际持有的币种显示。在只有人民币钱包的账户上强制 `USD`，
    会得到人民币余额配美元成本，设置页会在阈值下面明说这一点。把余额换算成美元需要汇率，而本插件按设计没有汇率来源。
54. **所有成本数字一起变化。** 15 秒实时烧、轮次平均、会话总计、以及最近轮次表的每一行，都会在币种改变时按 token 数重新计价，
    因此对比表内部始终可比。把过去轮次用一种币种、当前轮次用另一种币种混在一张表里，会让这张表唯一的作用——比较任务——失效。

node --test

说明文字配色、坐标精度统一、原点锚定、阻止图表撑宽面板、本轮/会话合并行、轮询间隔是秒而不是 60 秒的缓存窗口）。
